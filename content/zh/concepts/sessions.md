# 会话

## 概述

在 OpenClaw 中，**会话**是代理与用户或系统之间交互的核心上下文单元。每个会话都包含了完整的对话历史、工具调用记录、执行状态和用户偏好设置。

## 会话类型

### 1. 直接消息会话
- **一对一对话**：代理与单个用户之间的私人对话
- **连续性维护**：保持对话历史的连贯性
- **上下文隔离**：确保不同用户之间的隐私隔离

### 2. 群组/频道会话
- **多参与者对话**：在群组或频道中的对话
- **广播与响应**：代理同时与多个用户交互
- **上下文共享**：所有参与者共享相同的对话上下文

### 3. 系统会话
- **内部处理**：代理执行后台任务时的会话
- **自动化工作流**：定时任务、事件处理等
- **无用户界面**：通常不涉及直接用户交互

## 会话管理

### 会话标识
每个会话都有唯一的标识符，通常采用以下格式：
- `代理:<agentId>:<mainKey>` - 主会话标识
- `代理:<agentId>:<channel>:<peerId>` - 特定频道和参与者的会话

### 会话范围配置
通过 `dmScope` 参数控制直接消息会话的分组方式：

| 范围设置 | 描述 | 适用场景 |
|---------|------|---------------|
| `main` (默认) | 所有直接消息共享主会话 | 单用户设置 |
| `per-peer` | 按发送者隔离会话 | 多用户收件箱 |
| `per-channel-peer` | 按频道+发送者隔离会话 | 多用户多频道设置 |
| `per-account-channel-peer` | 按账户+频道+发送者隔离会话 | 多账户多频道设置 |

### 安全直接消息模式
对于多用户设置，强烈建议启用安全直接消息模式，以防止用户之间的上下文泄露。

**问题示例**：
- Alice 向代理发送私人医疗预约信息
- Bob 询问"我们刚才在讨论什么？"
- 如果没有会话隔离，代理可能使用 Alice 的上下文回答 Bob

**解决方案**：
```json
{
  "会话": {
    "dmScope": "per-频道-peer"
  }
}
```

## 会话生命周期

### 创建
- 用户首次与代理交互时自动创建
- 根据配置确定会话类型和范围
- 分配唯一会话标识符

### 维护
- 持续记录对话历史和工具调用
- 定期清理过期内容
- 优化存储和检索性能

### 终止
- 用户明确结束对话
- 会话超时（可配置时间）
- 系统清理资源

## 会话状态存储

### 网关作为唯一真相源
所有会话状态都由**网关**拥有和管理。UI 客户端（macOS 应用、WebChat 等）必须向网关查询会话列表和令牌计数，而不是读取本地文件。

### 远程模式
在远程设置中，会话状态通过安全隧道同步，确保所有客户端看到一致的状态。

## 最佳实践

1. **合理配置会话范围**：根据实际使用场景选择合适的 `dmScope` 设置
2. **启用安全模式**：多用户环境下务必启用安全直接消息模式
3. **定期清理**：配置会话修剪策略，防止存储膨胀
4. **监控使用情况**：定期检查会话数量和资源使用情况
5. **身份链接**：使用 `会话.identityLinks` 将同一用户在不同频道的身份关联起来
